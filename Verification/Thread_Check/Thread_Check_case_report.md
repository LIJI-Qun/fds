# FDS Thread_Check 算例详细报告

**算例目录**：`F:\DESK\1FireDynamicsSimulation\SHENBBAO\Verification\Thread_Check`  
**文件**：`race_test_1.fds`、`race_test_4.fds`、`README.MD`。  
**定位**：这是并行程序正确性测试，不是火灾模型精度验证。目标是让同一离散问题在非 OpenMP 单线程和 OpenMP 四线程配置下产生相同的温度、速度时间历程，以暴露共享变量的竞态条件（race condition）。

## 1. 分类和验收目标

| 分类 | 算例 | 运行配置 | 主要输出 | 通过条件 |
|---|---|---|---|---|
| 单线程基线 | `race_test_1` | README 指定为非 OpenMP FDS、1 核 | `TMP`、`VEL` | 作为确定性基准 |
| OpenMP 并行对照 | `race_test_4` | README 指定为 OpenMP FDS、4 核 | `TMP`、`VEL` | 与基线逐时间点一致 |

README 的明确标准是：同一域内给定点的温度和速度时间历程应相同。如失败，建议使用 Intel Inspector 追踪数据竞争。这里“相同”指同版本、同编译选项除线程模式外的可重复计算结果；不应把不同 FDS 版本、不同浮点编译器或不同 MPI 划分的差异归类为单纯线程竞态。

## 2. 物理与并行路径

```text
圆形 n-hexane pool fire --> 气相燃烧/浮力流 --> 六块非均匀网格交换
                                                        |
单线程 FDS  --------------------------------------------+--> TMP(t), VEL(t)
OpenMP 4 线程 FDS ---------------------------------------+--> TMP(t), VEL(t)
                                                        |
                                              同时刻逐值比较，定位不确定性
```

### 2.1 `race_test_1`：单线程参考解

**问题描述与验证目的。** 中央小型圆形正庚烷池火置于障碍物顶面，周围布置六个尺寸和分辨率不同的网格块。火羽流、反应、网格接口和设备采样共同形成足够复杂的工作负载，使未保护的线程共享写入更容易表现为温度或速度随时间偏离。该输入卡本身并不验证 n-hexane 的真实燃烧速率，而是给线程测试提供单线程数值基线。

**采用模型。** 采用 FDS 气相扩散燃烧与混合分数反应路径，燃料为 `N-HEXANE`，`CO_YIELD=0.100`、`SOOT_YIELD=0.010`。圆形 `VENT` 使用 `RADIUS=0.030 m`，表面燃料质量通量为 `0.0185 kg/(m2 s)`，并套用从 0.3896 缓慢降至 0.318 的 `RAMP_MF`。圆形初始面积为 `pi x 0.03^2=0.002827 m2`，初始实际燃料流量约为 `0.0185 x 0.3896 x 0.002827 = 2.04e-5 kg/s`，用于产生小尺度、快速演化火羽流。

**网格与计算。** 总共六块网格：两侧主域各为 `14 x 18 x 32`、中心底部为 `30 x 30 x 20`、中心上部为 `6 x 6 x 28`、前后细长区各为 `6 x 6 x 32`。所有坐标界面均围绕中心 0.3 m 方形和 z=0.2 m 高度拼接；从给定 XB/IJK 可见局部网格尺度约为 0.05 m。`T_END=5 s`，`race_test_1` 的设备输出间隔 `DT_DEVC=0.1 s`。

**边界条件。** 火源安放在 `XB=-0.04..0.04, -0.04..0.04, z=0.12 m` 的障碍物顶面，障碍物为 `0.2 x 0.3 x 0.12 m`。未显式列出的外边界采用 FDS 默认外边界处理；输入卡的检验焦点为网格之间的内部通信，不应把它设计为现实房间火灾的通风边界模型。

**工况参数和验收。** 设备位置均为 `(0,0,0.144 m)`，`TMP` 记录温度，`VEL` 记录速度标量，且关闭时间平均。输出 CSV 应作为基线保留，并且运行命令、FDS 可执行文件版本、线程环境变量、CPU 型号都应与并行对照同时记录。

### 2.2 `race_test_4`：四线程 OpenMP 对照

**问题描述与模型。** 该输入卡的几何、网格、反应、火源、障碍物、探针位置均与 `race_test_1` 相同，目的就是将唯一的实质变量放在运行命令：使用支持 OpenMP 的 FDS 可执行程序和 4 个线程。它同时覆盖反应源项、压力求解、边界/网格接口更新、设备取样等可能存在共享写入的路径。

**网格与计算。** 仍为六网格、5 s、相同 0.05 m 量级空间分辨率。应将 `OMP_NUM_THREADS=4`（或 FDS 平台规定的等效方式）与 OpenMP 版本二进制一起记录；仅在命令窗口开启四个逻辑处理器而没有调用 OpenMP 版本，并不构成有效对照。

**边界条件。** 与单线程卡完全相同：中心 6 cm 直径圆形 n-hexane 质量源置于 0.12 m 高障碍顶面，外边界不另行指定。这样任何输出差异都不应由物理输入造成。

**工况参数和验收。** 本卡的 `DT_DEVC=0.5 s`，而 `race_test_1` 为 0.1 s。这是静态输入中唯一影响直接逐行比较的重要差别，因此不能把两个 CSV 原样逐行比较。应以共同时间点 `t=0,0.5,1.0,...,5.0 s` 对齐 `TMP`、`VEL`；更严格的做法是将两卡的 `DT_DEVC` 临时统一后运行，但这会改变官方原卡，应在工作副本完成，不能覆盖基准卡。

| 参数 | 两例共同值 | 线程对照差异 |
|---|---|---|
| 网格 | 6 块，约 0.05 m | 无 |
| 计算时长 | 5 s | 无 |
| 燃料/火源 | n-hexane，R=0.03 m，0.0185 kg/(m2 s) | 无 |
| 探针 | (0,0,0.144 m)，TMP/VEL | 无 |
| 设备间隔 | 基线 0.1 s | OpenMP 卡 0.5 s |
| 执行方式 | 非 OpenMP、1 核 | OpenMP、4 线程 |

## 3. 建议比较流程

1. 在相同提交版本和同一机器上构建/选取单线程与 OpenMP 可执行文件；禁止混用不同 FDS 版本。
2. 运行 `race_test_1`，再在相同工作目录副本中以 4 线程运行 `race_test_4`；不要并发运行两次测试，避免共享输出文件或 CPU 资源干扰。
3. 读取两个 `*_devc.csv`，将基线重采样/筛选到 0.5 s 公共时间点，计算 `dT=T_4-T_1`、`dV=V_4-V_1`。
4. 检查每一时刻差值。若项目要求 bitwise repeatability，则格式化前的数值和时间列必须相同；若平台只承诺数值等价，应事先定义绝对/相对容差，并保留容差理由。
5. 若某次运行失败、另一次正常，或差异随重复运行改变，优先认定为竞态风险；按 README 建议用 Intel Inspector 进行线程检查。

## 4. 输入卡审查与限制

| 发现 | 影响与建议 |
|---|---|
| README 称两张卡“identical”，但 `CHID` 与 `DT_DEVC` 分别为 0.1 s、0.5 s | 物理定义一致，但 CSV 采样不一致；比较必须按公共时间点对齐。 |
| `RAMP_MF` 第二点在 10 s，而模拟只到 5 s | 不是错误；5 s 内仍处于线性下降段，实际倍率约从 0.3896 降至 0.3538。 |
| 外边界未显式指定 `OPEN` | 对线程确定性测试不必然是问题，但本卡不应用于评估真实空间通风。 |
| 输出只含一个温度和一个速度探针 | 足以做最小竞态筛查，但不能保证所有并行路径正确；出现通过结果不能替代完整回归测试集。 |

原始 `.fds` 和 `README.MD` 未修改。
