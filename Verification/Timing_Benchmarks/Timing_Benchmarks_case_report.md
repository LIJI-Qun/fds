# FDS Timing_Benchmarks 算例详细报告

**算例目录**：`F:\DESK\1FireDynamicsSimulation\SHENBBAO\Verification\Timing_Benchmarks`  
**覆盖范围**：16 张 FDS 卡，`openmp_test64a`--`h` 与 `openmp_test128a`--`h`，另含生成模板 `makecase.bat`。  
**定位**：这些卡用于测量 FDS/OpenMP 的计算耗时和线程缩放，绝非燃烧、毒性、辐射或烟气工程精度验证。验收输出是壁钟时间、每步耗时、吞吐率及加速比，物理场仅用于保持具有代表性的 CFD 工作负载。

## 1. 分类

| 分类 | 数量 | 算例 | 网格/时长 | 用途 |
|---|---:|---|---|---|
| 中等规模、长时间基准 | 8 | `openmp_test64a`--`h` | 64^3=262,144 cells，10 s | 减弱启动/写盘固定开销，比较线程数或编译优化对稳定吞吐率的影响 |
| 大规模、短时间基准 | 8 | `openmp_test128a`--`h` | 128^3=2,097,152 cells，1 s | 提高单步计算负载，考察内存带宽、缓存和 OpenMP 负载均衡 |

字母 a--h 不携带不同物理工况：静态卡除 `CHID` 外内容相同。它们通常是为不同执行命令、线程数、硬件节点或重复样本预留的独立输出名；实际线程数必须由运行脚本/环境变量记录，不能从输入卡字母推断。

## 2. 标准问题与模型

```text
  XMIN/XMAX/YMIN/YMAX/ZMAX：OPEN
       +------------------------+
       |                        |
       |  methane + water vapor |  1 m cube
       |                        |
       +==== 100 C, VEL=-0.1 ===+  ZMIN HOT inlet
                         |
                 DEVC: WALL CLOCK TIME ITERATIONS
```

**问题描述与验证目的。** 在 1 m 立方开放域底部施加 100°C、向域内 `VEL=-0.1 m/s` 的热进气面，域内定义甲烷和水蒸气物种，运行一个短暂三维热/流动计算。目标是让压力、速度、标量输运和 I/O 都参与计时，得到可跨版本比较的工作负载。它没有 `REAC`、`HRRPUA`、热解、液滴或复杂几何，因此不应将其解释成甲烷燃烧器。

**采用模型。** FDS 低马赫数流动、压力泊松求解、默认热/物种输运、开放边界与指定 VENT 速度/温度边界。`METHANE` 和 `WATER VAPOR` 的定义保证物种数据表路径被加载，但输入中没有将其作为指定质量源或燃料反应；性能差异主要来自网格规模、时间步和线程调度，而不是化学反应刚性。

## 3. 代表算例详细分析

### 3.1 `openmp_test64a`：64^3 稳态吞吐基准

**问题描述与验证目的。** 64^3 均匀网格覆盖 1 m 立方域，模拟 10 s。总单元数 262,144，网格尺度 `dx=dy=dz=1/64=0.015625 m`。较长的物理时间减少启动、初始化与两帧输出在总耗时中的占比，适合比较同一主机上 1、2、4、8 等线程数的平均迭代耗时。

**网格与计算。** 一块 `IJK=64,64,64` 网格，`XB=0..1 m` 三方向；`T_END=10 s`，`NFRAMES=2`、`DT_DEVC=0.1 s`。时间步由 FDS 稳定性控制自动选取，故性能报告必须同时记录迭代次数，不能只以“10 秒物理时间的总 wall time”比较不同版本。设备 `WALL CLOCK TIME ITERATIONS` 位于域中心 `(0.5,0.5,0.5)`，用于获取迭代计时信息。

**边界条件。** 五个面 `OPEN`；z=0 为 `HOT` 表面，`TMP_FRONT=100°C`、`VEL=-0.1 m/s`。负号对应 FDS 面法向约定下由底部向计算域推进的流动，目的是产生非零速度和热输运。没有实体、火源、辐射设置或燃烧反应。

**工况参数及报告指标。** 每个线程配置至少重复 3 次，清除前一次输出或使用独立工作目录。报告 `W_p`（总壁钟时间）、`N_iter`、平均 `w_p=W_p/N_iter`、加速比 `S_p=W_1/W_p` 和并行效率 `E_p=S_p/p`。同时记载 CPU 型号、核心/NUMA、内存频率、FDS git 版本、编译器、线程绑核及是否关闭睿频，否则结果不可横向解释。

### 3.2 `openmp_test128a`：128^3 内存/并行负载基准

**问题描述与验证目的。** 该例把空间分辨率提升为 128^3，总单元数为 2,097,152，是 64^3 的 8 倍；物理时间缩短为 1 s。它更接近内存带宽和大数组访问受限的求解工作载荷，用于发现线程数增加后速度无法线性提升、NUMA 跨节点访问或内存容量不足等问题。

**网格与计算。** `IJK=128,128,128`、`XB=0..1 m`，均匀网格尺度 0.0078125 m。`T_END=1 s`、`NFRAMES=2`、`DT_DEVC=0.1 s`；尽管模拟物理时间较短，网格数大，计时仍应记录 `N_iter`。由于 FDS 输出和初始化占比在短算例中可能显著，推荐除了总时间外另报告稳态迭代段的平均值，或确保所有配置采用同一计时窗口。

**边界条件。** 与 64^3 完全相同：z=0 的 100°C、-0.1 m/s 指定热流动面，其他五面开放。保持物理边界不变使网格规模成为主要差别，但 CFL 时间步随 dx 缩小通常也会改变，因此 64^3 与 128^3 的总耗时不应简单按 8 倍单元数预期。

**工况参数及报告指标。** 除线程缩放指标外，应报告单元吞吐率 `N_cell x N_iter / W_p`，以及每物理秒成本 `W_p/T_END`。128^3 的内存占用更高，正式基准前应记录系统可用内存和是否发生分页；一旦分页，所得时间不再代表 FDS 的计算性能。

| 参数 | `openmp_test64*` | `openmp_test128*` |
|---|---:|---:|
| 网格 | 64 x 64 x 64 | 128 x 128 x 128 |
| 单元数 | 262,144 | 2,097,152 |
| dx | 0.015625 m | 0.0078125 m |
| 物理时间 | 10 s | 1 s |
| 输出 | 2 frames，DEVC=0.1 s | 2 frames，DEVC=0.1 s |
| 物理边界 | 同一 HOT + 5 OPEN | 同一 HOT + 5 OPEN |
| 主要用途 | 长时间平均吞吐 | 大内存网格的并行扩展 |

## 4. 推荐基准工况矩阵

| 组别 | 输入卡 | 建议线程数 | 重复数 | 关键记录 |
|---|---|---:|---:|---|
| 小网格缩放 | `openmp_test64a`--`h` | 1,2,4,8（不超过物理核心数） | >=3 | 总时间、迭代数、`w_p`、S、E |
| 大网格缩放 | `openmp_test128a`--`h` | 1,2,4,8（按内存与核心配置） | >=3 | 同上，外加内存/NUMA/分页状态 |
| 可重复性检查 | 任一固定卡 | 固定 p | >=3 | 最大/最小/均值/标准差，排除后台负载异常 |

为避免伪加速，应固定 CPU 频率策略、线程绑定、进程亲和性和输出目录；每次运行应只启动一个 FDS 进程。不同字母卡可避免 CHID 输出覆盖，但不能自行设定 OpenMP 线程数。

## 5. 输入卡审查

| 发现 | 影响与建议 |
|---|---|
| 16 张 FDS 卡的功能参数除 CHID 外一致，64 与 128 仅网格/时间不同 | 正确的性能比较应把“字母”解释为运行样本/配置标签，而非物理变体。 |
| `makecase.bat` 模板写的是 64^3、`T_END=1.0`、设备 `CPU TIME` | 现有 `openmp_test64*` 卡为 `T_END=10.0`，且设备改为 `WALL CLOCK TIME ITERATIONS`；模板与提交的卡不同步，维护时不可直接运行模板覆盖现有基准卡。 |
| 输入卡注释指向 `makecase.sh`/`makecases.sh`，目录中实际提供的是 `makecase.bat` | 存在跨平台脚本或历史命名残留。更新基准前应确认权威模板和生成流程。 |
| 输入定义了 CH4 与水蒸气但未定义 `REAC` | 这是计时工况设计，不是遗漏燃烧模型；不能据此检查火焰或 HRR 精度。 |
| `WALL CLOCK TIME ITERATIONS` 是性能诊断量 | 必须与 `*_cpu.csv`/输出日志中的迭代计数共同解释，不能把单个设备值直接当总运行耗时。 |

## 6. 性能结论的表达边界

本目录可支持的结论是“在已声明硬件、FDS 二进制和线程设置下，某网格规模的壁钟耗时、加速比与效率”。它不能支持“FDS 火灾模型更准确”或“64^3 与 128^3 网格解已收敛”等结论。若要将时间基准与数值正确性绑定，必须另行使用 Verification 回归结果和相同版本的输出比较。

原始 `.fds` 与 `makecase.bat` 未修改。
